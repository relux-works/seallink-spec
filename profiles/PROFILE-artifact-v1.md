## 1. Scope and Module Boundary

`PROFILE-artifact-v1` builds an optional, self-contained **Artifact Gatekeeper & Tier-2 SPV Verification Profile** on top of SealLink Core's `0x14 LOG_CHECKPOINT` transparency/denial logs (`SPEC-05 §6`, `SL-CONT-012`) and `seallink-release/1` records (`SPEC-05 §7`, `SL-CONT-013`).

- **Optional module gate (`SL-ARTF-001`, `decided`):** Implementations that do **NOT** declare `artifact-notarization` MUST refuse `seallink-ticket/1` and `seallink-tier2-name-history/1` at wire ingress Step 7b (`SPEC-01 §7`) with **`ACTION_UNSUPPORTED`** and zero journal writes.
- **Canonical artifact identity (`SL-ARTF-002`, `decided`):** Every `seallink-ticket/1`, `seallink-release/1`, and `artifact-notarization` `seallink-notary/1` MUST carry `target_sha256 == H_tag("seallink-artifact-id/1", JCS({"digest", "scheme"}))` strictly excluding `params` (`registry/artifact-schemes.json`). Under `scheme = "fsverity-sha256"`, `digest` MUST equal Linux kernel `FS_IOC_MEASURE_VERITY` (`SHA256(256-byte little-endian fsverity_descriptor)` with `version = 1` [1B], `hash_algorithm = 1` [1B], `log_blocksize = 12` [1B -> 4096B zero-padded Merkle tree], `salt_size = 0` [1B], `__reserved_0x04 = 0` [4B LE], `data_size = len(file)` [8B LE], 32B `root_hash`, 208 trailing zero bytes; empty-file digest `3d248ca542a24fc62d1c43b916eae5016878e2533c88238480b26128a1f1af95`), and `params` MUST equal `{"version": 1, "hash_alg": "sha256", "block_size": 4096, "salt_hex": ""}` (non-empty `salt_hex` refused `WIRE_MEMBER`; ticket mismatch refused **`TICKET_PROOF_INVALID`**).

## 2. Artifact Tickets (`seallink-ticket/1`) and Gatekeeper Policy (`SL-ARTF-003`, `decided`)

`seallink-ticket/1` (`schemas/profile-artifact.schema.json#/$defs/ArtifactTicket`) bundles an `artifact_identity`, canonical `target_sha256`, optional `release` (`seallink-release/1`, REQUIRED whenever `notarizations` is empty), `notarizations[0..32]`, and optional `absent_notary_proofs[]`.

A Gatekeeper evaluates a ticket against a closed `GatekeeperPolicy` (`mode ∈ {"standard", "hardened"}`, `trusted_notaries[]`, `quorum_m`, `required_claims[]`, optional `trusted_release_issuers[]`, `require_release`, `release_floor`, `allow_reinstatement`, optional `bootstrap_expires_at`; when `require_release` is not `true`, `quorum_m >= 1` is REQUIRED and `release_floor` is FORBIDDEN):

1. **Journal continuity & observation order, hardened bootstrap ban/expiry:** If `journal` is supplied, `journal.check_continuity()` MUST run FIRST (`JOURNAL_LOST` / `JOURNAL_FENCED`), followed immediately by `check_chain_observation()` (`CHAIN_OBSERVATION_VOID`, `CHAIN_MISMATCH`, `CHAIN_UNHEALTHY`, `CHAIN_NODE_DISAGREEMENT`, `CHAIN_CLOCK_ERROR`, `CHAIN_TIP_STALE`) before reading ticket proofs or mutating state. `bootstrap_expires_at` is FORBIDDEN when `mode == "hardened"` (`WIRE_MEMBER`). When present in `standard` mode, if `now >= bootstrap_expires_at`, refuse **`ARTIFACT_POLICY_DENIED`**. `trusted_notaries[]` MUST NOT contain duplicate `(name, registration)` entries (`ARTIFACT_POLICY_DENIED`).
2. **Provisional gossip deny-wins:** Any wire-valid `seallink-log-revocation/1` signed by a trusted notary's or release issuer's live `link.<role>` targeting `target:<target_id>|*`, `act:<trusted_act_id>|*`, or `rel:<release_id>|*` MUST immediately refuse **`ARTIFACT_POLICY_DENIED`** without mutating durable `FencedJournal.log-head`.
3. **Release verification & `release_floor`:** When `release` is present (or `require_release == true`), verify `release.target_sha256 == target_id` (`TICKET_PROOF_INVALID`), issuer `NamePin` (matching `(name, registration)`, surviving cold `owner_policy` rotation) + `allowed_product_prefixes[]` + `log_id` (`ARTIFACT_POLICY_DENIED`; release issuers without a pinned `log_id` in policy authorize `eternal` `0x09` releases only, while `log_tracked` releases require a matching pinned `log_id` — or `predecessor_chain` handover — and `release_floor` enforces monotonic `release_seq >= release_floor[product_id]` across both lifecycles), and `verify_release` (`0x09` eternal or `0x14` `log_tracked`, supporting optional `release_state_inclusion` and `predecessor_chain` for rotated `link.release` keys and `O(1)` handovers, propagating `NOTARY_LOG_COMPROMISED` and `CRED_ISSUER_CLOSED` unconditionally).
4. **Present notarizations, `verdict ∈ {"pass", "fail", "inconclusive"}`, and `target:` SMT veto (`SL-ARTF-004`, `decided`):**
   - Untrusted third-party notarizations in a multi-notary ticket MUST be skipped BEFORE inspecting `act_kind` or `target_sha256`. Duplicate entries for the same trusted notary — within `notarizations[]`, within `absent_notary_proofs[]`, OR appearing simultaneously in BOTH `notarizations[]` and `absent_notary_proofs[]` — MUST refuse **`TICKET_PROOF_INVALID`**.
   - Every trusted notarization MUST verify `network` & `genesis` (`CHAIN_MISMATCH`), `act_kind == "artifact-notarization"`, `target_sha256 == target_id` AND `artifact_target_id(details.artifact_identity) == target_id` (`TICKET_PROOF_INVALID`), and durable `credential` closure (`CRED_REVOKED_FOR_CAUSE` / `SEAL_SPENT`).
   - Each trusted `log_tracked` notarization MUST verify `0x14` batch inclusion, ancestor chain, unspent `vout 1` (`next_log_vout == 1`) on `head_checkpoint` (`TICKET_PROOF_INVALID` if matured successor exists), durable log closure (`NOTARY_LOG_COMPROMISED`), `0x0b` compromise (`CRED_ISSUER_CLOSED`), heartbeat freshness (`heartbeat_max_blocks` unless `terminal == true`), optional `predecessor_chain` (`<= 16`), `act:<act_id>|*` SMT proof (with optional `act_state_inclusion`), AND **`target:<target_id>|*` SMT proof** (with optional `target_state_inclusion`) against `head_checkpoint.denials_root`. (Trusted notaries configured without `log_id` in `GatekeeperPolicy` accept `eternal`/`revocable` `0x04` acts only and cannot issue `target:` absent-notary proofs.)
   - **Global deny-wins across ALL claim verdicts:** `"pass"` counts toward `quorum_m`; **`"fail"`** is an unconditional global deny-wins veto (**`ARTIFACT_POLICY_DENIED`**) evaluated across ALL trusted notarizations in the ticket regardless of entry order (even if earlier entries already reached `quorum_m`!), and notaries emitting `"fail"` MUST publish a companion `target:<target_id>|*` revocation in the same checkpoint; **`"inconclusive"`** abstains (neither counts toward `quorum_m` nor triggers a veto).
   - For every trusted notary with a pinned `log_id` absent from `notarizations[]`: in **`hardened`** mode, an `absent_notary_proof` proving `target:<target_id>|*` is not revoked in that notary's fresh `head_checkpoint` (with unspent `next_log_vout` and optional `target_state_inclusion`) is **MANDATORY** (`TICKET_PROOF_INVALID` if omitted or duplicate `log_id`, `ARTIFACT_POLICY_DENIED` if revoked, `NOTARY_LOG_COMPROMISED` if the log is closed, `CRED_ISSUER_CLOSED` on `0x0b`).
   - **Quorum rule (including `required_claims == []`):** When `required_claims` is non-empty, every `claim_id` in `required_claims[]` MUST achieve `>= quorum_m` distinct trusted `"pass"` votes; when `required_claims == []` and `quorum_m >= 1`, at least `quorum_m` distinct trusted notarizations MUST contain at least one `"pass"` claim (an all-`"inconclusive"` notarization MUST NOT satisfy `quorum_m`; `ARTIFACT_POLICY_DENIED` otherwise).

## 3. Tier-2 Consensus-Exact `SegWitNameUpdateProof` and Namecoin AuxPoW (`SL-ARTF-005`, `decided`)

For lightweight Gatekeepers verifying Namecoin name histories via paginated `seallink-tier2-name-history/1` pages (`schemas/profile-artifact.schema.json#/$defs/Tier2NameHistoryPage`), **Tier-2 `SegWitNameUpdateProof` is normatively scoped to `owner_policy.kind ∈ {"key", "multisig"}`** (native SegWit `P2WPKH` and `P2WSH` `m-of-n` multisig up to `15-of-15`, matching all notary and release-publisher names; `branch` seal templates are outside Tier-2 SPV scope and refuse `CHAIN_SCRIPT_UNSUPPORTED`).

Every `seallink-tier2-name-history/1` page MUST enforce **unbroken registration-to-tip chain continuity** (any violation refuses **`TICKET_PROOF_INVALID`**, or **`WIRE_MEMBER`** at Step 8 schema check):
- **Wire `headers[]` & `trusted_checkpoint` anchoring:** `Tier2NameHistoryPage` carries `headers[]` directly on the wire (every element validating against `BlockHeaderProof` in `schemas/profile-artifact.schema.json#/$defs/BlockHeaderProof`). Heights MUST be strictly contiguous (`h[i] == h[i - 1] + 1`) with `prev_block_hash == block_hash(h[i - 1])`, PoW & `CAuxPow::check` MUST pass on every header, MTP(11) (`nTime > median(prev 11 headers)`), `+2h` future timestamp bound (`nTime <= current_time + 7200`), and difficulty retarget / non-retarget `nBits` equality MUST pass at every step (`§3.1`). Whenever a `trusted_checkpoint` (`{height, block_hash, epoch_start_time?}`) is configured in `GatekeeperPolicy` (RECOMMENDED on `main`), the verifier MUST anchor `headers[]` to exact `(trusted_checkpoint.height, trusted_checkpoint.block_hash)` and derive any mid-epoch retarget `epoch_start_time` strictly from the pinned `trusted_checkpoint` (NEVER trusting an unanchored server-supplied `epoch_start_time`!). When `updates[]` is non-empty on `network = "main"`, `headers[]` covering every `updates[i].block_height` MUST be supplied (skipping PoW verification via omitted `headers[]` is forbidden on `main`).
- **Unbroken name-UTXO chain (`OP_NAME_FIRSTUPDATE` + `OP_NAME_UPDATE`) & cursor `owner_policy` continuity:**
  - On page 1 (no `cursor_txid`): `updates[]` MUST be non-empty (`minItems: 1`, else `WIRE_MEMBER` at Step 8), and `updates[0]` MUST either BE the registration's own `OP_NAME_FIRSTUPDATE` (`txid == registration.txid` and `name_vout == registration.vout`, spending `prevout_tx`'s `OP_NAME_NEW` output whose `hash20 == HASH160(rand || name)` verified via BIP-143) OR be an `OP_NAME_UPDATE` spending exact `(registration.txid, registration.vout)`.
  - On continuation pages (`cursor_txid`, `cursor_vout`, `cursor_height`, and optional `cursor_owner_policy` present): if `updates[]` is non-empty, `updates[0]` MUST spend exact `(cursor_txid, cursor_vout)` at `block_height >= cursor_height` and `< cursor_height + name_expiry_blocks`, starting policy verification from `cursor_owner_policy` (when provided, else `expected_owner_policy`).
  - For every `i >= 1`: `updates[i]` MUST spend exact `(updates[i - 1].txid, updates[i - 1].name_vout)` (proving zero skipped updates, zero injected cross-registration updates, and zero hidden `0x0b` breaks!), satisfy `updates[i].block_height >= updates[i - 1].block_height` and `< updates[i - 1].block_height + name_expiry_blocks`, and when `updates[i].block_height == updates[i - 1].block_height` MUST have identical `block_hash` and strictly increasing `tx_index > updates[i - 1].tx_index`.
  - **P2WPKH & P2WSH cold rotation, `owner_authored`, `name-value.schema.json`, and `0x0b`/`0x13` surfacing:** When an update transfers `owner_policy` (`new_trailing_script_pubkey != prev_trailing_script_pubkey`), `owner_authored` MUST be marked **`false`** on the transfer transaction itself (requiring a subsequent self-update authored by the new `owner_policy` to restore `owner_authored = true`, matching `SL-LDGR-007`), and the verifier advances `cur_owner_policy` from EITHER the P2WPKH pubkey (2-item witness) OR P2WSH `m-of-n` `witnessScript` (`wit[-1]` parsed via `parse_p2wsh_multisig_script`, supporting cold `P2WPKH <-> P2WSH` rotations!). When `next_cursor` is present, `next_cursor` MUST equal `{"height": updates[-1].block_height, "txid": updates[-1].txid, "vout": updates[-1].name_vout, "owner_policy": final_owner_policy}` (carrying the evolved `owner_policy` across pages). Every decoded name value MUST pass BOTH 520-byte Restricted JCS AND closed `schemas/name-value.schema.json` validation (`TICKET_PROOF_INVALID`), plus `SLNK` outer-before-semantic framing (`SPEC-02 §5.2`), surfacing confirmed `0x0b` compromise breaks and failing closed **`ORIGIN_STATUS_INCOMPLETE`** on unresolved owner-authored `0x13` frames (unless explicitly resolved via `origin_bundle`).

Every individual `SegWitNameUpdateProof` MUST pass **all 7 consensus-exact Namecoin Core `nc28.0` checks** (any failure refuses **`TICKET_PROOF_INVALID`**):

1. **Anti-64-byte leaf forgery, empty `scriptSig`, & `nVersion`:** Non-witness serialized byte lengths of `coinbase_tx`, `tx`, and `prevout_tx`, plus full serialized length of `tx`, MUST ALL be strictly **`!= 64` bytes**; `tx` MUST carry SegWit marker/flag `00 01`, `nVersion == 0x7100`, AND empty `script_sig == b""` on the spent name input (native SegWit v0 consensus rule).
2. **Coinbase structure & exact depth `D_tree`:** `len(coinbase_tx.vin) == 1` with null prevout `(00*32, 0xffffffff)`; `coinbase_merkle_branch` folds `txid(coinbase_tx)` at `index == 0` into `block_header.hashMerkleRoot`, fixing exact block Merkle depth `D_tree = len(coinbase_merkle_branch) >= 1`.
3. **Strict depth & `CVE-2012-2459` guard:** `tx_index >= 1`, `len(txid_branch) == len(wtxid_branch) == len(wtxid_coinbase_branch) == D_tree`, rejecting odd-position duplicate siblings; `txid_branch` proves `txid(tx)` at `tx_index` in `hashMerkleRoot`.
4. **BIP-141 witness commitment:** Extract commitment `[6:38]` from the **LAST** `coinbase_tx.vout[]` matching prefix `6a24aa21a9ed` (`len >= 38`); `coinbase_tx.vin[0].witness` MUST hold exactly one 32-byte `witness_reserved_value`.
5. **Witness tree binding:** `wtxid(tx)` at the same `tx_index` via `wtxid_branch` produces `wtxid_root`; `wtxid_coinbase_branch` folds `00*32` at `index == 0` into the same `wtxid_root`; `SHA256d(wtxid_root || witness_reserved_value) == witness_commitment`.
6. **Stripped BIP-143 `scriptCode` with CompactSize prefix (`OP_NAME_FIRSTUPDATE` & `OP_NAME_UPDATE`):** `prevout_tx` matches the spent name input (`OP_NAME_NEW` for `OP_NAME_FIRSTUPDATE`, confirming `HASH160(rand || name) == prev_hash20` and `new_output.trailing_script_pubkey == compile(expected_owner_policy)`; or `OP_NAME_FIRSTUPDATE`/`OP_NAME_UPDATE` for `OP_NAME_UPDATE`, confirming `prev_output.trailing_script_pubkey == compile(expected_owner_policy)`). Strip the Namecoin prefix (`kind ∈ {"key", "multisig"}`) and compute the BIP-143 sighash including `varint(len(scriptCode)) || scriptCode` (`76a914<20B>88ac` for `P2WPKH`, `witnessScript` for `P2WSH`).
7. **Consensus-exact BIP-66 DER + `SIGHASH_ALL` (accepting high-S) & Registrar-Funded `OP_NAME_FIRSTUPDATE` (`SL-LDGR-007`):** Every ECDSA signature in the name input witness MUST be canonical BIP-66 DER with trailing `0x01` (`SIGHASH_ALL`) and verify over the BIP-143 sighash. **Tier-2 verifiers MUST NOT reject consensus-valid high-S (`S > N/2`) signatures** already mined into Namecoin blocks (signers SHOULD emit low-S per `GUIDE-01 §2` to satisfy standard relay policy). When `OP_NAME_FIRSTUPDATE` spends a distinct registrar/funding native SegWit `OP_NAME_NEW` (`prev_output.trailing_script_pubkey != compile(expected_owner_policy)`), verify that native SegWit `OP_NAME_NEW` spend (`P2WPKH` BIP-143 `SIGHASH_ALL` + BIP-66 DER, or `P2WSH` witnessScript SHA-256 hash match + BIP-66 DER ECDSA verification if standard `m-of-n` multisig, else witnessScript hash match) and mark `owner_authored = false` (requiring a subsequent owner-authored `OP_NAME_UPDATE` before treating the value as owner-authored, matching `SPEC-02 §3.3` `SL-LDGR-007`).

### 3.1 Namecoin AuxPoW (`CAuxPow::check`) and Difficulty Retarget (`SL-ARTF-006`, `decided`)

When validating 80-byte Namecoin block header chains (`BlockHeaderProof`, where `header_hex` is the exact first **80 bytes** [160 hex chars] of `getblockheader <hash> false` — excluding any serialized AuxPoW trailer — matching Namecoin Core `nc28.0` `src/pow.cpp`, `src/auxpow.cpp`, `src/validation.cpp`, and `src/kernel/chainparams.cpp`):
- **Network parameters:**
  - `main`: `nAuxpowStartHeight = 19200`, `nLegacyBlocksBefore = 19200`, `fStrictChainId = true`, `fPowNoRetargeting = false`, `name_expiry_blocks = 36000`, `powLimit = 0x00000000ffffffffffffffffffffffffffffffffffffffffffffffffffffffff`.
  - `regtest`: `nAuxpowStartHeight = 0`, `nLegacyBlocksBefore = 0`, `fStrictChainId = true`, `fPowNoRetargeting = true`, `name_expiry_blocks = 30`, `powLimit = 0x7fffffffffffffffffffffffffffffffffffffffffffffffffffffffffffffff`.
  - *(Informative `testnet` reference if ever enabled by profile: `nAuxpowStartHeight = 0`, `nLegacyBlocksBefore = -1` [no legacy blocks on testnet], `fStrictChainId = false`, `fPowAllowMinDifficultyBlocks = true`, `name_expiry_blocks = 36000`, `powLimit = 0x0000000fffffffffffffffffffffffffffffffffffffffffffffffffffffffff` [7 leading hex zeros].)*
- **Base `nVersion`, `IsLegacy()`, & timestamp rules (`nc28.0` `ContextualCheckBlockHeader`):**
  - On `height == 0`, enforce exact pinned genesis hash match (`nBits` / AuxPoW checks apply from `height >= 1`).
  - Let `base_ver = nVersion & 0x000000ff` and `chain_id = nVersion >> 16`. Whenever `height >= nLegacyBlocksBefore` (non-legacy block), require `chain_id == 0x0001`; on `main` post-SegWit (`height >= 475000`) and `regtest` (`height >= 1`), require `base_ver >= 4` (matching `nc28.0` `BIP65`/`BIP66` rejection `-25 bad-version(0x00010002)`).
  - Require `header[H].nTime > MTP(11)` (median of the 11 preceding headers' timestamps whenever 11 prior headers are present) AND `header[H].nTime <= current_time + 7200` (`+2h` future bound when `current_time` is supplied).
- **Non-AuxPoW header (`nVersion & 0x00000100 == 0`):** On heights `>= nLegacyBlocksBefore`, require `chain_id == 0x0001` and `block_hash <= target(nBits)`.
- **AuxPoW (`nVersion & 0x00000100 != 0`):** Require `height >= nAuxpowStartHeight`, `chain_id == 0x0001`, **`parent_header.nVersion & 0x00000100 == 0`** (`!parentBlock.IsAuxpow()`), **`(parent_header.nVersion >> 16) != 1` whenever `fStrictChainId == true`**, `len(chain_branch) <= 30` (with 32-byte hashes), `parent_header` PoW `<= target(nBits)`, **`!parent_coinbase.vin.empty()`** (exact `nc28.0` `CAuxPow::check` guard), `coinbase_branch` at `index == 0` into `parent_header.hashMerkleRoot`, merged-mining magic `fabe6d6d` immediately preceding `aux_merkle_root` (or omitted iff `aux_merkle_root` starts within the first 20 bytes of `parent_coinbase.vin[0].scriptSig`, matching Namecoin Core `CAuxPow::check`, where synthetic regtest parent coinbases MAY carry empty `vout`), `merkle_size == (1 << len(chain_branch))`, `merkle_nonce`, expected slot `GetExpectedIndex(merkle_nonce, chain_id, merkle_size)`, and `chain_branch` for `block_hash`.
- **Exact Namecoin `nc28.0` difficulty retarget (`src/pow.cpp:47-55`):**
  - On `regtest` (`fPowNoRetargeting == true`), `nBits` does not retarget (do NOT apply mainnet retarget math at `H == 2016` on `regtest`).
  - On `main` for every non-retarget height `H % 2016 != 0`: MUST enforce **`header[H].nBits == header[H - 1].nBits`**.
  - On `main` at retarget boundary `H % 2016 == 0` (`H > 0`): `nBlocksBack = 2016` if `(H - 1) >= nAuxpowStartHeight and H > 2016` (so `nHeightFirst = H - 2017` for all mainnet epochs `H >= 20160`!), else `2015` (`nHeightFirst = H - 2016` for early pre-AuxPoW epochs `H <= 18144`). Clamp `actual_timespan = block[H - 1].nTime - block[nHeightFirst].nTime` strictly to `[302400, 4838400]`, compute `new_target = min(powLimit, (old_target * actual_timespan) // 1209600)`, and require `header[H].nBits == target_to_compact(new_target)` (verified against real Namecoin mainnet archival heights `24192`, `30240`, and post-SegWit `733824` in `vectors/ledger-scripts-and-opreturn.json`). Header checkpoints starting mid-epoch MUST supply pinned `epoch_start_time = block[nHeightFirst].nTime` via local `trusted_checkpoint`.
- **Explicit Tier-2 SPV trust boundary:** A single `seallink-tier2-name-history/1` page cryptographically proves **prefix authenticity** of the name's UTXO chain up to `verified_tip_height` (zero forged updates, zero skipped middle updates, exact `owner_policy` evolution, and all `0x0b`/`0x13` frames within that prefix). Because Namecoin block headers contain no UTXO state root, a single Tier-2 server could withhold tail updates, newer `0x0b` breaks, or a newer `0x14` `head_checkpoint` spend occurring *after* `updates[-1]`; therefore **tail completeness and UTXO/log-head freshness** for `log_tracked` Gatekeepers MUST rely on cross-querying **`k >= 2` independent header/RPC providers** or a Tier-1 full node (`SPEC-02 §1.1`, `OQ-002`).

## 4. Curator Integration (`CIP-0007` / `CIP-0008` / `CIP-0034`)

- Canonical signing (`CIP-0008`) maps directly to SealLink Restricted JCS + BIP-340 (`SPEC-01`).
- Curator content digests use `scheme = "works.relux.curator/content-v2"` (`registry/artifact-schemes.json`); revocations (`CIP-0007`) map 1-to-1 to the closed 3-key universe `act:<act_id>|*`, `rel:<release_id>|*`, and `target:<target_id>|*` inside `0x14` logs.
- Phase-1 bootstrap Gatekeeper deployments MUST set `bootstrap_expires_at <= now + 90 days` in `standard` mode and transition to `hardened` mode (without `bootstrap_expires_at`) once multi-notary quorum is operational.

## 5. Security Considerations

- **Unified 100% `CLOSE` on log fraud:** A verified `seallink-log-fraud/1` durably records `NOTARY_LOG_COMPROMISED` and blocks 100% of acts and releases from that `log_id` in both `standard` and `hardened` Gatekeeper modes.
- **Tier-2 source diversity:** Production Tier-2 Gatekeepers SHOULD cross-check headers and `seallink-tier2-name-history/1` pages across `k >= 2` independent header/RPC providers (`OPEN-QUESTIONS.md` `OQ-002`).
- **HSM role separation:** `link.notary` and `link.release` keys require dedicated BIP-340 signers; `log_seal` (ECDSA) MAY reside in standard KMS/HSM custody (`GUIDE-01 §1`).
