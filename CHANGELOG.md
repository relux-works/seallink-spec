# Changelog

All notable changes to the SealLink Protocol Specification are documented in this file.

## [1.0.0-draft.3] - 2026-11-23

Authoritative draft of the SealLink v1.0 Protocol Specification with hardened Reference Verifier Core, closed-schema ingress enforcement, full device-key cryptography, HTML/PDF web publication (`https://seallink.org/`), and Namecoin Core `nc28.0` P2A regtest evidence:

- **Normative Core Specifications (`spec/SPEC-00` through `spec/SPEC-07`):** Architecture, Restricted RFC 8785 JCS wire format, universal `SignatureSet` / `guardian_approvals[]` policy binding (BIP-340 plus RFC 8032 Ed25519 and strict low-S NIST P-256 for device-authorized types), 7-predicate Constraint Algebra, Namecoin Core `nc28.0` ledger binding (`NAME_NEW` / `NAME_FIRSTUPDATE` / `NAME_UPDATE`, `ScriptPolicy`, Merkle batch `0x02`, mandatory TRUC v3 for zero-fee `P2A` CPFP, `CHAIN_UNHEALTHY` on zero healthy comparison peers), 520-byte multi-role identity with on-chain role-policy pins and pinned `NamePin` providers, eternal origin certificates with salted privacy commitments, explicit `disposer_pk`/`arbiter_pk`/`challenger_pk`, authenticated `status_seal` / `roster_seal` / `recovery_seal` continuation spines (including `status_seal` institutional DoS boundary and forbidden `retain_active`/`retain_vacant` on `disposer_pk`/`arbiter_pk` rotation), direct initial (`0x12`) and acyclic two-stage (`0x0d`/`0x0e`) guardianship with mandatory incoming guardian assent, roster transitions (`0x0f`) with intentional fail-safe ward grant halt, 4-class linear verifier-derived quorums, structural consistency invariants (`SL-ORIG-016`), N-party salted contracts with unique `party_id` (supporting co-parties with identical legal roles) and symmetric 1-to-1 `seallink-assent/1`, universal grants with R8.5/R8.6 depth-2 re-delegation, atomic dual-account (`own` + `row`) multi-quota reservation/settlement and rollback, acyclic single-use consumption (`0x11`), recipient-authenticated admission pipeline, crash-in-effect-window `uncertain` recovery, fenced anti-rollback journals, and replaceable service portability.
- **Standard Profiles (`profiles/`):** `PROFILE-mail-v1.md` (`mail`) and `PROFILE-agent-v1.md` (`agent-session`, including normative `strict_drop` `agent/guardian-message` under `event_class = "effect_grant"`), backed by closed argument and result JSON Schemas.
- **Machine-Readable SSOT (`registry/`, `schemas/`):** 6 JSON registries (30 object types, 22 key roles, 84 refusal codes, 18 `SLNK` `OP_RETURN` action definitions `0x01`–`0x12` with `0x06` reserved, 8 standard service types, 7 Constraint Algebra predicates) and 12 Draft 2020-12 JSON Schemas published live at `https://seallink.org/releases/v1.0.0-draft.3/schemas/`.
- **Executable Conformance Vectors, Reference Verifier Core & Mutation Testing (`vectors/`, `tools/`, `conformance/`):** 9 vector suites (unit vectors with Ed25519 + low-S P-256, 4 full RFC 8448-style traces including dual-account multi-quota settlement, co-tenant `party_id` assents, both positive `name_recovery` continuation branches, and crash-in-effect-window recovery, a schema-validated `84/84` refusal coverage matrix, and an adversarial `security-conformance.json` suite), pure-Python Reference Verifier Core (`tools/seallink_verifier.py`) with derived `ChainView` history/witness evaluation and verifier-check mutation self-tests executed in CI, and two-node Namecoin Core `nc28.0` `P2A` 1p1c regtest evidence (`conformance/p2a-regtest/`).
- **Governance, Guides & Publishing:** `CONFORMANCE.md`, `OPEN-QUESTIONS.md`, `SLIP-TEMPLATE.md`, `guides/GUIDE-01-custody-and-signers.md` (including TLS SPKI pinning & managed CDN guidance), per-rule `archive/rule-inventory.md`, single-file Markdown bundle builder (`tools/build_bundle.py`), HTML / Print-to-PDF site & live schema publisher (`tools/build_site.py`), and GitHub Actions CI / Release / Cloudflare Pages deploy pipelines.
