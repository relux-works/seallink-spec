# Changelog

All notable changes to the SealLink Protocol Specification are documented in this file.

## [1.0.0-draft.4] - 2026-11-23

Authoritative draft of the SealLink v1.0 Protocol Specification with fail-closed Reference Verifier Core (`require_jsonschema=True` by default), `100.0%` (`231/231`) exhaustive refusal-branch verifier mutation coverage, policy-scoped `0x0b` compromise handling, per-`row_ordinal` quota accounting, lossless 64-entry `Receipt.settlements`, live two-node Namecoin Core `nc28.0` four-trace regtest artifacts, and HTML/PDF web publication (`https://seallink.org/`):

- **Normative Core Specifications (`spec/SPEC-00` through `spec/SPEC-07`):** Architecture, Restricted RFC 8785 JCS wire format, universal `SignatureSet` / `guardian_approvals[]` policy binding (BIP-340 plus RFC 8032 Ed25519 and strict low-S NIST P-256 for device-authorized types), 7-predicate Constraint Algebra, Namecoin Core `nc28.0` ledger binding (`NAME_NEW` / `NAME_FIRSTUPDATE` / `NAME_UPDATE`, `ScriptPolicy`, Merkle batch `0x02`, mandatory TRUC v3 for zero-fee `P2A` CPFP, `CHAIN_UNHEALTHY` on zero healthy comparison peers), 520-byte multi-role identity with on-chain role-policy pins and pinned `NamePin` providers, eternal origin certificates with salted privacy commitments, explicit `disposer_pk`/`arbiter_pk`/`challenger_pk`, authenticated `status_seal` / `roster_seal` / `recovery_seal` continuation spines (including `status_seal` institutional DoS boundary, forbidden `retain_active`/`retain_vacant` on `disposer_pk`/`arbiter_pk` rotation, and explicit operational note on temporary guardian vacancy during `appointment_delay_blocks`), direct initial (`0x12`) and acyclic two-stage (`0x0d`/`0x0e`) guardianship with mandatory incoming guardian assent, roster transitions (`0x0f`) with intentional fail-safe ward grant halt, 4-class linear verifier-derived quorums, structural consistency invariants (`SL-ORIG-016`), N-party salted contracts with unique `party_id` (supporting co-parties with identical legal roles) and symmetric 1-to-1 `seallink-assent/1`, policy-scoped `0x0b` compromise reconstruction (preserving successor policies installed via valid `OP_NAME_UPDATE` and distinct roles), universal grants with R8.5/R8.6 depth-2 re-delegation, per-`row_ordinal` `row` quota accounting and journal replay, lossless `Receipt.settlements` (`maxItems: 64` with `account`, `window`, and conditional `row_ordinal`), acyclic single-use consumption (`0x11`), recipient-authenticated admission pipeline, crash-in-effect-window `uncertain` recovery, fenced anti-rollback journals, and replaceable service portability.
- **Standard Profiles (`profiles/`):** `PROFILE-mail-v1.md` (`mail`) and `PROFILE-agent-v1.md` (`agent-session`, including normative `strict_drop` `agent/guardian-message` under `event_class = "effect_grant"`), backed by closed argument and result JSON Schemas.
- **Machine-Readable SSOT (`registry/`, `schemas/`):** 6 JSON registries (30 object types, 22 key roles, 84 refusal codes, 18 `SLNK` `OP_RETURN` action definitions `0x01`–`0x12` with `0x06` reserved, 8 standard service types, 7 Constraint Algebra predicates) and 12 Draft 2020-12 JSON Schemas published live at `https://seallink.org/releases/v1.0.0-draft.4/schemas/`.
- **Executable Conformance Vectors, Reference Verifier Core, 100% Mutation Audit & Live `nc28.0` Regtest (`vectors/`, `tools/`, `conformance/`):** 9 vector suites (`196` crypto/logic checks, `312` live verifier checks, `1312` Draft 2020-12 schema checks), pure-Python Reference Verifier Core (`tools/seallink_verifier.py`, fail-closed `require_jsonschema=True` default), exhaustive multi-core mutation auditor (`tools/mutation_audit.py`: **`231/231` = `100.0%` refusal branches killed**), standalone two-node `nc28.0` `P2A` 1p1c regtest proof (`conformance/p2a-regtest/`), and live two-node `nc28.0` four-trace regtest proof (`conformance/traces-regtest/`, covering `P2WSH` 2-of-3 `namepsbt`, `guardian_slot_pending` CSV `non-BIP68-final` + post-delay `0x0e`, `single_use_1_of_2` `0x11`/revoke, TRUC v3 `P2A` CPFP revoke, and `agent/guardian-message` with raw tx hexes and live `Tier1Verifier` verdicts).
- **Governance, Guides & Publishing:** `CONFORMANCE.md`, `OPEN-QUESTIONS.md`, `SLIP-TEMPLATE.md`, `guides/GUIDE-01-custody-and-signers.md` (including TLS SPKI pinning & managed CDN guidance), mechanically validated `archive/rule-inventory.md` (`0` unregistered refusal codes), single-file Markdown bundle builder (`tools/build_bundle.py`), duplicate-ID-free HTML / Print-to-PDF site & live schema publisher (`tools/build_site.py`, automated `0` duplicate-ID and `0` broken-anchor self-check), and GitHub Actions CI / Release / Cloudflare Pages deploy pipelines.
