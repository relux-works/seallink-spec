# Changelog

All notable changes to the SealLink Protocol Specification are documented in this file.

## [1.0.0-draft.7] - 2026-11-24

Authoritative self-contained v1.0 draft of the SealLink Protocol Specification with fail-closed Reference Verifier Core (`require_jsonschema=True` by default, strict `require_observation_bracket` support), two-phase atomic admission and late signed-receipt commit (`admit_and_reserve()` -> `commit_result(receipt_env)`, zero synthetic receipt hashes, witness-verified restart replay), native `P2WSH` `m-of-n` (`2 <= n <= 5`) `BranchKeySpec` institutional custody for origin branch authorities, target-authority binding (`GRANT_TARGET_UNAUTHORIZED` and `registry/actions.json`), deterministic `x-seallink-refusal` schema precedence, full `30/30` object-type and `85/85` refusal-code execution, multi-operator verifier mutation auditing achieving **`100.0%` across all three operators** (`refusal-return` `278/278`, `wrong-code` `278/278` with `0` exceptions, exact numeric `boundary` `113/113` with `0` exceptions), hardened cold-observer Namecoin Core RPC adapter (`tools/nc_rpc_adapter.py`), live two-node Namecoin Core `nc28.0` five-trace cold-observer regtest proof (`32` live verdicts), and immutable tag-driven HTML/PDF web publication with explicit `404.html` (`https://seallink.org/`):

- **Normative Core Specifications (`spec/SPEC-00` through `spec/SPEC-07`):**
  - *Wire & Cryptography (`SPEC-01`):* Restricted RFC 8785 JCS, deterministic `x-seallink-refusal` schema-to-refusal precedence (`WIRE_TYPE -> WIRE_MEMBER -> WIRE_INTEGER -> WIRE_KEY -> WIRE_SIGNATURE -> WIRE_CONSTRAINT -> CHAIN_SCRIPT_UNSUPPORTED`), universal `SignatureSet` / `guardian_approvals[]` policy binding (BIP-340 plus RFC 8032 Ed25519 rejecting small-order/non-canonical points and strict low-S NIST P-256), curve-point validation across all key fields, and 7-predicate Constraint Algebra.
  - *Ledger & Names (`SPEC-02`, `SPEC-03`):* Namecoin Core `nc28.0` binding (`txindex=1` + `namehistory=1` multi-registration historical lookups, `SIGHASH_ALL` current-owner authorship check rejecting transfer-written values until new-owner self-update, history-based permanent `link.origin` detection, active-chain reorg exclusion, opening/closing observation brackets with unified decision clock and closed-bracket `pre_effect_recheck`, `clock_mode="operational"` mandatory on `main`, root-only `0x02` Merkle batches, exact `(seal_txid, seal_vout + 1)` grant-issuance linkage, mandatory TRUC v3 for zero-fee `P2A` CPFP, 520-byte multi-role identity with Unicode case-fold alias blocking and cross-role/manifest key disjointness).
  - *Origin & Guardianship (`SPEC-04`):* Eternal origin certificates with salted privacy commitments, **`BranchKeySpec`** supporting either a single compressed secp256k1 key or compact native `P2WSH` `m-of-n` (`2 <= n <= 5`, distinct x-coords) for `disposer_pk`/`arbiter_pk`/`challenger_pk`/`arbiter_or_both.arbiter`, pre-binding invariant `h_origin < h_firstupdate`, `binding_seal` spend verification, authenticated `status_seal` / `roster_seal` / `recovery_seal` continuation spines, `effective_delay_blocks >= appointment_delay_blocks` with pre-effective `0x0d` ban on `new_vacant`, BIP-68 CSV `0x0e` witness/sequence enforcement, Path A (calendar majority `T` with mandatory `majority_commitment` disclosure and `MTP < T`) & Path B (confirmed `capacity/1` with exact `subject_new_owner_policy` handover) emancipation, forbidden `name_recovery.mode = "none"` on ward origins, former-guardian `0x10` lockout post-emancipation, and `D-1` recovery-only burn semantics on malformed `recovery_seal` spends.
  - *Contracts & Credentials (`SPEC-05`):* Multi-ward `verify_contract_assents` (`origin_bundles_by_oid`), 72-hour assent freshness at `0x07` `anchor_time`, closed `MachineClauseTerms` mechanical narrowing, distinct issuer/recipient contract party binding, `IssuancePrep` without dead assent address lists, framework window & `not_after_unix` nesting, `seallink-credential/1` calendar `not_after_unix` and `0x0a` `seallink-credential-withdrawal/1`, eternal credential `subject.name_pin` evaluated at `h_anchor` plus `subject.mode = "origin"`, policy-scoped `0x0b` compromise reconstruction, full cryptographic `seallink-notary/1`, `seallink-verdict/1`, and `seallink-termination/1` verification.
  - *Grants, Delegation, Journals & Optional v1.0 Modules (`SPEC-06`, `SPEC-07`):* Target-authority binding (`GRANT_TARGET_UNAUTHORIZED` and `registry/actions.json`), mandatory profile quotas (`seallink/*` namespace, zero-debit `agent/session` `checkpoint`/`halt`), `SL-GRNT-004` `not_after_height <= issuer_name_expiry_at_issuance`, full depth-2 `required_act` notary & `recipient_rule` (`exact_key` / `exact_name` / `member_class`) enforcement, two-phase atomic `admit_and_reserve()` -> `commit_result(real_receipt)` with zero synthetic `sha256(invocation_id)` fallbacks, `UNCERTAIN` on unsettled retry, `INVOKE_REPLAY` on missing receipt blob, witness-verified `FencedJournal.replay_persisted_entries` (`JOURNAL_LOST` / `JOURNAL_FENCED`) with discriminated `ClosureSubject`, plus fully specified & vector-tested optional-declaration v1.0 modules (`CONFORMANCE.md §1.1`): Bearer Sessions (`SPEC-06 §5`), 4-Step Exclusive Service Migration (`SPEC-07 §2`), and Federated Screening & Contour A PII Disclosure (`SPEC-07 §3`).
- **Standard Profiles (`profiles/`):** `PROFILE-mail-v1.md` (`mail`) and `PROFILE-agent-v1.md` (`agent-session`, including mandatory `pinned_ward_origin_id` and `strict_drop` `agent/guardian-message`), backed by closed argument/result JSON Schemas and `registry/actions.json`.
- **Machine-Readable SSOT (`registry/`, `schemas/`):** 7 JSON registries (30 object types, 22 key roles, 85 refusal codes, 7 standard profile actions, 18 `SLNK` `OP_RETURN` action definitions `0x01`–`0x12` with `0x06` reserved, 8 standard service types, 7 Constraint Algebra predicates & `seallink/*` quota kinds) and 12 Draft 2020-12 JSON Schemas with deterministic `x-seallink-refusal` annotations published live at `https://seallink.org/releases/v1.0.0-draft.7/schemas/`.

- **Governance, Guides & Publishing:** `CONFORMANCE.md` (with `§1.1` optional-declaration v1.0 modules), `OPEN-QUESTIONS.md` (`OQ-007` resolved via `BranchKeySpec` and `OQ-012` `K = 432` decided), `SLIP-TEMPLATE.md`, `guides/GUIDE-01-custody-and-signers.md`, mechanically validated `archive/rule-inventory.md` (`113` rules, `0` unregistered refusal codes), deterministic single-file Markdown bundle builder (`tools/build_bundle.py`), tag-only immutable HTML/Print-PDF site & live schema publisher (`tools/build_site.py` emitting explicit `404.html`, automated `0` duplicate-ID and `0` broken-anchor checks), and GitHub Actions CI / Release / Cloudflare Pages deploy pipelines.
